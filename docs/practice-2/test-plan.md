# Практика 2 — план тестирования

## Окружение и входные условия

- Локальный Docker Compose СМП; CMS — `http://localhost:8081`, Authorization — `http://localhost:8083`.
- Для обычных сценариев контейнеры CMS, Authorization и PostgreSQL запущены и имеют статус `Up … (healthy)` в выводе `docker ps`.
- Используются отдельные синтетические карты и известные BIN. Валюта — `643`, денежные значения — в копейках.
- Зафиксированы версия приложения, конфигурация и дата прогона. Время запроса соответствует времени стенда; проверки границ месяцев не выполняются в момент смены даты.
- Каждая независимая проверка начинается с заданного баланса и использования лимитов. Для срока действия и накопленных сумм, которые нельзя задать публичным API, подготавливаются фикстуры в локальной тестовой БД. Чужие карты не изменяются.

## Порядок выполнения

| Этап | Действие | Результат |
|---|---|---|
| 1 | Сверить требования, классы и границы | Разделы 1—4 тест-дизайна |
| 2 | Подготовить карты и снимки состояния | PAN, лимиты, баланс, срок и счётчики известны |
| 3 | Проверить успешную авторизацию, статусы, границы и приоритеты | AUTH-01—AUTH-11 |
| 4 | Проверить недоступность CMS и идентификаторы | AUTH-12, AUTH-13, AUTH-15; после проверки восстановить зависимость |
| 5 | Проверить операции CMS на независимых данных | CMS-01—CMS-10, CMS-12—CMS-16 |
| 6 | Сгенерировать PICT-набор и проверить покрытие допустимых пар | `pict/model.txt`, `pict/cases.txt` |
| 7 | Выполнить строки PICT по общему сценарию из тест-дизайна | Фактические ответы и изменения состояния для PW-кейсов |
| 8 | Оформить отклонения и проверить комплект артефактов | Баг-репорты |

## Фиксация результатов

Результаты записываются в [test-results.md](test-results.md): подготовлены строки для всех AUTH-, CMS- и PW-кейсов, включая отдельные варианты параметризованных тестов. Материалы прогона сохраняются в `docs/practice-2/evidence/<ID-прогона>/<ID-теста>/`, ссылки на них добавляются в журнал результатов.
